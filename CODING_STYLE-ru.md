# Стиль кода

Я начинал писать в [стиле Plan 9](http://man.cat-v.org/plan_9/6/style),
но понимаю, что это не самый популярный стиль, поэтому готов на компромиссы.
Старайтесь сильно не отклоняться, чтобы код выглядел единообразно во всём проекте.

В качестве примеров, оба этих стиля (или что-то среднее) допустимы:

```
type
functionname(args)
{
	if(a == b){
		s1;
		s2;
	}else{
		s3;
		s4;
	}
	if(x != y)
		s5;
}

type functionname(args)
{
	if (a == b) {
		s1;
		s2;
	} else {
		s3;
		s4;
	}
	if (x != y)
		s5;
}
```

Этот стиль (или что-то более экстремальное) крайне не приветствуется:

```
type functionname ( args )
{
  if ( a == b )
  {
    s1;
    s2;
  }
  else
  {
    s3;
    s4;
  }
  if ( x != y )
  {
    s5;
  }
}
```

То есть:

* Ставьте открывающую скобку на той же строке, что и управляющая конструкция
* Ставьте открывающую скобку на следующей строке после определений функций и структур/классов
* Пишите `else` на той же строке, что и скобки
* Не ставьте скобки вокруг одиночных операторов
* Выносите возвращаемый тип функции на отдельную строку
* Используйте для отступов **TAB** (табуляцию)

Что касается менее косметических решений, вот несколько рекомендаций:

* Не используйте магические числа там, где в исходном коде был enum или что-то подобное.
Даже если вы не знаете точного значения, лучше назвать что-то `FOOBAR_TYPE_4`, чем просто `4`,
поскольку `4` будет использоваться в других местах, и вы не сможете легко увидеть, где ещё используется это значение enum.

* Не копируйте код из IDA «как есть», приведите его в порядок
* Используйте правильные типы. В частности:
    * не используйте типы вроде `__int16`, для этого у нас есть `int16`
    * не используйте `unsigned`, для этого у нас есть typedef'ы
    * не используйте `char` ни для чего, кроме символов; используйте `int8`, `uint8` или `bool`
    * даже не думайте использовать win32-типы (`BYTE`, `WORD` и т.д.), если вы не пишете win32-специфичный код
    * объявляйте указатели как `int *ptr;`, а не `int* ptr;`

* Что касается имён переменных, оригинальный исходный код GTA не был написан в едином стиле,
но вот некоторые наблюдения:
    * многие переменные используют подобие венгерской нотации, например:
    * `m_` может использоваться для членов класса (в основном тех, что считаются приватными)
    * `ms_` для (в основном приватных) статических членов
    * `f` — float, `i` или `n` — целое число, `b` — boolean, `a` — массив
    * **не** используйте `dw` для `DWORD` и т.п., мы не программируем под win32

* В целом старайтесь, чтобы код выглядел так, будто его могла написать R*
